   * - 段階

   * - 単体テスト

   * - 結合テスト
     - 機能をまたいで機能要件を満たすか
     - テストチーム
     - 対象（ :doc:`test_cases` ）
   * - 総合テスト
     - 非機能要件（性能・可用性など）を満たすか
     - テストチーム
     - 対象外（別途「総合テスト計画書」で作成予定）
   * - 受入テスト
     - 業務で使えるか
     - ユーザー部門
     - 対象外

2. 結合テストの範囲
-------------------

- すべての機能要件（FR）を 1 件以上のテストケースで検証する。
- 非機能要件（NFR）のうち、結合テストで確認できる :need:`NFR_001` （応答時間の目安）と :need:`NFR_005` （権限）は結合テストでも確認する。それ以外は総合テストで確認する。

3. 完了条件
-----------

#. すべてのテストケースを実施し、合格していること。
#. 機能要件のカバレッジが 100 % であること（ :doc:`../traceability/coverage` で確認）。
#. 重大度「高」の未解決不具合が 0 件であること。

4. テスト環境
-------------

- 本番と同じ構成のステージング環境（AP 1 台構成）
- 外部システムはスタブを使う（EDI は SFTP フォルダ、運送会社 API はモックサーバ、会計システムは共有フォルダの出力確認）
- テストデータ: 顧客 20 社、商品 50 品目、在庫は商品ごとに 0 / 10 / 100 個のパターンを用意する

.. newbie:: 「カバレッジ 100 %」の意味

   ここでいうカバレッジは「すべての機能要件に、それを検証するテストケースが 1 件以上ある」という意味です（コードの行カバレッジとは別物です）。
   Sphinx-Needs では、テストケースから要件に ``verifies`` リンクを張っておけば、漏れている要件を自動で一覧にできます。

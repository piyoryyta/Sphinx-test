CRUD 図
=======

機能・バッチ（行）がどのエンティティ（列）を登録（C）・参照（R）・更新（U）・削除（D）するかを示します。

この表は手で書いていません。:doc:`functions` と :doc:`batches` の各 need に書いた ``creates`` / ``reads`` / ``updates`` / ``deletes`` のリンクから、ビルドのたびに自動で作り直しています。
表の下には、登録（C）する機能がないエンティティなどを自動でチェックした結果が出ます（問題がなければ何も出ません）。

.. crud-matrix::
   :rows: fn, bat
   :cols: ent

凡例
----

.. list-table::
   :widths: 10 90

   * - C
     - Create（登録）
   * - R
     - Read（参照）
   * - U
     - Update（更新）
   * - D
     - Delete（削除）。顧客・商品は使用停止で扱うため D はない。受注明細の D は変更時の明細削除。

レビュー観点
------------

- 列（エンティティ）を縦に見て、C がない、または R しかないエンティティはないか。
  あれば、データを作る機能が漏れているか、初期データの移行で作る前提かを確認する。
- 行（機能）を横に見て、機能の説明と C / R / U / D が合っているか。
- 同じエンティティを U する機能が多い場合（例: 在庫）、同時に更新したときの排他制御が設計されているか。

.. newbie:: CRUD 図で何がわかるか

   CRUD 図は「データの一生」を確かめる表です。
   たとえば在庫（ENT_003）の列を縦に見ると、商品登録で生まれ（C）、引当と出荷で変わり（U）、照会で見られる（R）ことがわかります。
   テーブルの項目を変えるときは、その列に印がある機能すべてに影響が出る可能性があります。

ドキュメントの全体像と読む順番
==============================

1. 工程とドキュメントの関係
---------------------------

システム開発は、大まかに「企画 → 要件定義 → 基本設計 → 詳細設計 → 製造 → テスト」の順に進みます。
前の工程の成果物が、次の工程のインプットになります。

.. mermaid::

   flowchart TB
     P[企画<br/>なぜ作るか] --> R[要件定義<br/>何を作るか]
     R --> B[基本設計<br/>どう作るか（外から見た姿）]
     B --> D[詳細設計<br/>どう作るか（中の作り）]
     D --> M[製造<br/>プログラムを書く]
     M --> T[テスト<br/>要件どおりか確かめる]
     T -.確かめる対象.-> R

2. ID の体系
------------

すべての要素に ID を付け、ID 同士をリンクでつないでいます。ID の頭の文字で種類がわかります。

.. list-table::
   :header-rows: 1
   :widths: 15 20 15 50

   * - 接頭辞
     - 種類
     - 工程
     - ひとことで言うと
   * - ISS
     - 課題
     - 企画
     - 今、困っていること
   * - BIZ
     - 業務
     - 要件定義
     - システム導入後の仕事の単位
   * - BR
     - 業務要件
     - 要件定義
     - 業務として、できるようになりたいこと
   * - FR / NFR
     - 機能要件 / 非機能要件
     - 要件定義
     - システムがすること / システムの品質
   * - FN / BAT
     - 機能 / バッチ
     - 基本設計
     - 画面から使う処理 / 自動で動く処理
   * - SCR / RPT / IF
     - 画面 / 帳票 / 外部IF
     - 基本設計
     - 人や他システムとの接点
   * - ENT
     - エンティティ
     - 基本設計
     - 業務で扱う情報のまとまり
   * - API / TBL
     - API / テーブル
     - 詳細設計
     - プログラムの入り口 / データの入れ物
   * - TC
     - テストケース
     - テスト
     - 要件どおりかを確かめる手順

3. リンクの種類
---------------

.. list-table::
   :header-rows: 1
   :widths: 20 35 45

   * - リンク
     - 向き
     - 意味
   * - ``satisfies``
     - BR → ISS・BIZ、FR・NFR → BR
     - 上流の要求を満たす
   * - ``realizes``
     - FN・BAT・IF → FR、SCR・RPT・API → FN、TBL → ENT
     - 上流の要件・機能を実現する
   * - ``verifies``
     - TC → FR・NFR
     - 要件を検証する
   * - ``creates`` / ``reads`` / ``updates`` / ``deletes``
     - FN・BAT → ENT
     - データを登録・参照・更新・削除する（CRUD 図の元）

4. 1 本の糸をたどってみる
-------------------------

まずは 1 つの要件を上から下までたどると、全体の関係がつかめます。おすすめは「受注登録」です。

#. :need:`ISS_001` FAX 受注の転記ミス（なぜ必要か）
#. :need:`BR_001` 受注情報を一元登録できること（業務として何がしたいか）
#. :need:`FR_001` 受注登録（システムが何をするか）
#. :need:`FN_001` 受注登録機能、 :need:`SCR_003` 受注登録画面（どう見せるか）
#. :need:`API_001` 受注登録 API、 :need:`TBL_001` 受注テーブル（どう作るか）
#. :need:`TC_001` 、 :need:`TC_002` （どう確かめるか）

同じつながりは :doc:`../traceability/trace_diagram` の図 2 でも見られます。

.. newbie:: 全部を読む必要はない

   最初から全ページを細かく読む必要はありません。
   「4. 1 本の糸をたどってみる」を一度やってから、担当する機能の周辺を深く読むほうが効率的です。

機能一覧¶

オンライン機能（画面から使う機能）の一覧です。夜間などに自動で動く処理は バッチ一覧 にあります。

各機能には次のリンクを書いています。

  • realizes: 実現する機能要件（FR）

  • creates / reads / updates / deletes: 操作するエンティティ（ENT）。CRUD 図 はこのリンクから自動で作られます。

受注¶

機能: 受注登録 FN_001
status: review
owner: 鈴木
category: 受注
実現する: FR_001
実現手段: API_001, SCR_003
登録 (C): ENT_004, ENT_005
参照 (R): ENT_001, ENT_002, ENT_003

受注ヘッダと明細を登録する。登録後、続けて 在庫引当 (FN_004) を呼び出して在庫を引き当てる。 受注番号は「年月日 + 4 桁連番」（例: 202704010001）で採番する。
機能: 受注取込（手動） FN_002
status: review
owner: 鈴木
category: 受注
実現する: FR_002
実現手段: SCR_004
登録 (C): ENT_004, ENT_005
参照 (R): ENT_001, ENT_002

EDI の受注 CSV を画面からアップロードして取り込む。 定時の自動取込（EDI 受注取込 (BAT_001)）と同じ取込ロジックを使う。
機能: 受注変更・取消 FN_003
status: review
owner: 鈴木
category: 受注
実現する: FR_003
実現手段: SCR_002, SCR_003
参照 (R): ENT_001, ENT_002
更新 (U): ENT_004, ENT_005
削除 (D): ENT_005

出荷指示前の受注を変更・取消する。明細の削除は物理削除、受注全体の取消は状態を「取消」にする（論理削除）。 変更・取消の後は 在庫引当 (FN_004) で引当をやり直す。

在庫¶

機能: 在庫引当 FN_004
status: review
owner: 鈴木
category: 在庫
実現する: FR_004
実現手段: API_002, SCR_003
参照 (R): ENT_004
更新 (U): ENT_003, ENT_005

受注明細ごとに有効在庫から引き当て、在庫の引当済数と明細の引当数を更新する。 画面からは直接呼ばず、受注登録 (FN_001) ・ 受注変更・取消 (FN_003) ・ EDI 受注取込 (BAT_001) から呼ばれる共通機能とする。
機能: 在庫照会 FN_005
status: review
owner: 鈴木
category: 在庫
実現する: FR_005
実現手段: SCR_005
参照 (R): ENT_002, ENT_003

商品ごとの実在庫・引当済数・有効在庫を表示する。

出荷¶

機能: 出荷指示 FN_006
status: review
owner: 鈴木
category: 出荷
実現する: FR_006
実現手段: RPT_001, RPT_002, SCR_006
登録 (C): ENT_006
参照 (R): ENT_001, ENT_004, ENT_005
更新 (U): ENT_004

当日出荷分の引当済み受注から出荷データを作り、受注の状態を「出荷指示済」にする。 ピッキングリスト（ピッキングリスト (RPT_001)）と納品書（納品書 (RPT_002)）を出力する。
機能: 出荷実績登録 FN_007
status: review
owner: 鈴木
category: 出荷
実現する: FR_007
実現手段: SCR_007
更新 (U): ENT_003, ENT_004, ENT_006

出荷完了を登録し、在庫の実在庫と引当済数を減らす。受注の状態を「出荷済」にする。

請求¶

機能: 請求締め FN_008
status: review
owner: 鈴木
category: 請求
実現する: FR_009
実現手段: RPT_003, SCR_008
登録 (C): ENT_007
参照 (R): ENT_001, ENT_005, ENT_006
更新 (U): ENT_006

締め日を指定して、対象顧客の出荷実績を集計した請求データを作り、請求書（請求書 (RPT_003)）を出力する。 集計した出荷には請求番号を記録し、二重に請求しないようにする。

🔰 新卒メモ: 「共通機能」に注目

在庫引当 (FN_004) （在庫引当）は画面を持たず、ほかの機能から呼ばれる部品です。 こうした共通機能は、呼び出し元が増えるほど修正の影響が広がります。修正するときは、CRUD 図 と トレース図 で影響範囲を確かめてください。
